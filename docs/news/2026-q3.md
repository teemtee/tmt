# tmt news 2026 Q3

What's new in tmt 1.76–1.79

## Safety & Security

* Granular feeling-safe control — a new `--allow-unsafe-behavior` option replaces the previous all-or-nothing [feeling-safe](https://tmt.readthedocs.io/en/stable/stories/features.html#/stories/features/feeling-safe) mode, letting you opt in to individual unsafe behaviors. The step-level `--feeling-safe` option is no longer supported.

* Guarded SSH options — `ssh-option` values that execute commands or set up network forwarding now require `--feeling-safe`, avoiding unexpected command injection.

* `--condition` requires feeling-safe — because it evaluates expressions via `eval()`, the `--condition` filter now requires `--feeling-safe`.

* Sandboxed Jinja templates — template rendering now runs in a sandboxed environment, limiting what rendered templates can access.

## Test Execution & Reporting

* `finish` runs before `report` — the step execution order changed so the [`finish`](https://tmt.readthedocs.io/en/stable/spec/plans.html#/spec/plans/cleanup) step now runs before the `report` step, so reports reflect the finished state of the run.

* Accurate durations across reboots — test result [duration](https://tmt.readthedocs.io/en/stable/spec/tests.html#duration) now records the real total across guest reboots and restarts instead of only the last invocation.

* reportportal multihost UUIDs — the `reportportal` plugin now saves all test UUIDs for multihost tests, keyed by `guest_name`.

* Subresult log paths fixed — custom [result](https://tmt.readthedocs.io/en/stable/spec/results.html) subresult logs now resolve relative to `TMT_TEST_DATA`.

## Artifact Verification

* Specific NVR installation — the [artifact](https://tmt.readthedocs.io/en/stable/plugins/prepare.html#artifact) plugin now installs the exact NVR when `verify` is used with a uniquely identified package.

* Clear error on missing RPMs — the artifact plugin now stops immediately with a clear message when no RPMs are downloaded, replacing a confusing copy error.

* Shared repository naming — a new `repository-name` key lets you name the shared aggregation repository used across artifacts.

* CentOS 7 support — artifacts can now be installed on CentOS 7, and Koji artifact URLs are fixed to use the build version and release.

## Recipes

* Disabled phases saved — the [recipe](https://tmt.readthedocs.io/en/stable/spec/recipe.html) file now records disabled phases, so they are preserved when the recipe is loaded.

* Expanded recipe guide — a new Recipes section in the guide documents inspecting and editing `recipe.yaml` and filtering with `tmt-recipe-tool`.

## Provisioning & Guests

* Image URL caching for virtual guests — the [virtual](https://tmt.readthedocs.io/en/stable/plugins/provision.html#plugins-provision-virtual-testcloud) plugin gains `use-image-cache` and `image-cache-age` keys; downloaded images are cached for 7 days by default.

* finish/shell in image mode — the [finish/shell](https://tmt.readthedocs.io/en/stable/plugins/prepare.html#shell) plugin now runs scripts immediately on image-mode guests instead of deferring them, so they actually execute.

* Robust SSH reconnection — reconnecting to a guest after reboot now retries when the SSH master process has died, fixing reboot-related reconnection failures.

* Guest-specific plan source script — the plan source script is now a per-guest file rather than shared, matching the earlier per-guest environment file fix.

* Container test termination — podman-executed tests now receive `SIGHUP`, ensuring their subprocesses terminate correctly.

## Prepare & Install

* `check-first` for installs — the install plugin exposes a `check-first` key (enabled by default) that checks whether a package is already present before installing, avoiding unintended upgrades.

* Only missing packages installed — package installation now passes only the missing packages to the package manager, preventing silent upgrades caused by dnf's `best=True`.

* Ansible inherits tmt environment — [ansible](https://tmt.readthedocs.io/en/stable/plugins/prepare.html#shell) playbooks now run with the tmt process environment inherited, so its variables are available to the playbook.

## Environment & Hardware

* Disk requirement list syntax — the dictionary form of the disk [hardware](https://tmt.readthedocs.io/en/stable/spec/hardware.html) requirement has been removed; use the list form instead.

## Framework & Checks

* Disabled checks skip package install — packages required by a check are no longer installed when the check is disabled with `enabled: false`.

## Other

* Python 3.12 required for the runner — the tmt runner now requires at least Python 3.12 (1.78 was the last release supporting Python 3.9). This does not affect guest compatibility.

* Multiple policies on the CLI — multiple [policies](https://tmt.readthedocs.io/en/stable/spec/policy.html) can now be passed on the command line.

* Flag key normalization — empty flag keys in fmf data now fall back to their default values instead of loading as `None`.

* Verbosity levels capped — verbose and debug levels are now limited to their defined range.

* Jira issue search refined — [Jira](https://tmt.readthedocs.io/en/stable/guide.html#link-issues) issue search now matches on words only, reducing spurious matches.

* Architecture detection — `uname -m` is now used instead of `arch` to detect the guest architecture, improving portability.
